# TDD Refactor

## 실행 순서

### 1. 컨벤션 파악

`CLAUDE.md`를 읽어 프로젝트의 네이밍 규칙·컴포넌트 패턴·스타일링 컨벤션을 파악한다.

### 2. 그린 확인

```bash
npm test
```

실패가 있으면 중단하고 사용자에게 보고한다. 이 스킬은 그린 상태에서만 시작한다.

### 3. 대상 파일 식별

```bash
git diff main...HEAD --name-only -- src/
```

- 테스트 파일(`*.test.ts`, `*.test.tsx`) 제외
- 남은 파일에 대해 아래 5가지 기준으로 검토

**점검 기준:**
| 기준 | 확인 내용 |
|------|-----------|
| 중복 제거 | 같은 로직이 반복되는가 |
| 네이밍 명확성 | 의도를 드러내는 이름인가 |
| 단일 책임 | 함수/컴포넌트가 너무 많은 일을 하는가 |
| 불필요한 복잡도 | 매직 넘버, 과도한 중첩, 불필요한 추상화 |
| CLAUDE.md 컨벤션 불일치 | 프로젝트 패턴과 어긋나는 코드 |

### 4. 대상 목록 보고 → 승인 대기

발견한 리팩터링 후보를 표로 제시한다:

```
| # | 파일:라인 | 기준 | 변경 내용 |
|---|-----------|------|-----------|
| 1 | ...       | ...  | ...       |
```

후보가 없으면 "리팩터링 대상 없음"을 보고하고 종료한다.
**사용자 승인 전에 코드를 수정하지 않는다.**

### 5. 항목별 적용

승인된 항목을 **하나씩** 처리한다:

1. 변경 적용
2. `npm test` 실행
3. 전체 통과 → 다음 항목으로
4. 실패 → 즉시 롤백 후 사용자에게 보고

### 6. 변경 요약 제공

완료 후 변경 전후를 간략히 요약한다.

---

## 제약

- 새 기능 추가 금지
- 테스트 파일(`*.test.ts/tsx`) 수정 금지
- `src/` 디렉토리 밖 수정 금지
- `git diff` 결과 파일 범위 밖 수정 금지
